# RAVEN AI Dialogue Credit System (Simulation)

نظام رصيد اختياري للحوار بالذكاء الاصطناعي.
القضية كاملة مجانية (أدلة + ألغاز + نهاية). المدفوع فقط طريقة الحوار بالـ AI.
عند نفاد الرصيد يعود اللاعب تلقائياً للحوار المكتوب.

## الوضع الحالي
- محاكاة فقط (`simulation: true`).
- لا يتم الاتصال بمزود دفع حقيقي.
- لا يتم استدعاء نموذج ذكاء اصطناعي حقيقي.
- لا تفعيل تحصيل أو نشر مدفوع.

## التشغيل المحلي

```bash
cd server
npm install
node src/index.js
# أو
npm test
```

السيرفر يعمل على المنفذ 4000 افتراضياً.

## الملفات المهمة
- `config.example.json` — إعداد بلا أسرار (انسخه إلى `config.json` وغيّر القيم).
- `migrations/001_init.sql` — ترحيل قاعدة البيانات.
- `src/index.js` — نقطة الدخول والمسارات.
- `src/services/paymentSimulator.js` — محاكاة بوابة الدفع.
- `src/services/aiSimulator.js` — محاكاة الردود (لا تخترع أدلة).
- `tests/credit.test.js` — اختبارات الحالات الأساسية.

## حساب التكلفة (قبل التسعير النهائي)
التكاليف في `config.example.json` تقديرية للمحاكاة فقط:
- تكلفة الرسالة التقديرية: متغير `ai.estimatedCostPerMessageUsd`.
- رسوم التحصيل: نسبة + مبلغ ثابت.
- الهامش: نسبة لكل باقة.

لا تستخدم هذه الأرقام في الإنتاج قبل قياس فعلي على المزود الحقيقي.

## مسار الدفع (محاكاة)
1. `POST /payments/create` → ينشئ طلب من السيرفر.
2. محاكاة الدفع عبر `POST /simulation/pay`.
3. إرسال الـ webhook إلى `POST /webhooks/payment` مع التوقيع.
4. التحقق من التوقيع + المبلغ + العملة قبل منح الرصيد.
5. منع التكرار عبر `idempotency_key` و `status = paid`.

## الحماية والحدود
- مفاتيح الخدمات في config فقط (لا تُرفع إلى Git).
- استهلاك الرصيد داخل transaction لمنع الاستهلاك المزدوج.
- حد أقصى لطول المحادثة وعدد الرسائل في الجلسة.
- الـ AI لا يضيف أدلة ولا يغير الفاعل ولا يفتح مراحل.

## ما هو ناقص (للإنتاج)
- ربط مزود دفع حقيقي (Moyasar / Tap / Stripe) مع التحقق الصحيح من التوقيع.
- ربط نموذج AI حقيقي مع حقن الحقائق فقط (RAG أو prompt ثابت).
- نظام استرداد حقيقي مرتبط بالبوابة.
- مراقبة الاستخدام والحدود الزمنية.
- مصادقة المستخدمين (حالياً userId نصي للمحاكاة).
- واجهة اللاعب لعرض الرصيد والباقات (يتم تصميمها بشكل منفصل).

## الاختبارات
شغّل `npm test` داخل مجلد `server`.
الاختبارات تغطي: إنشاء الدفع، منع التكرار، رفض توقيع خاطئ، منح الرصيد مرة واحدة، الرجوع للحوار المكتوب عند النفاد، استهلاك الرصيد مع الحفاظ على التقدم.
