# محاكي الرصيد المحلي — ليس خدمة بيع

هذا مسار تاريخي مستقل عن server/ai-dialogue والموقع. لا بوابة دفع أو نموذج حي، ولا حساب مستخدم موثوق. userId هو fixture محلي. لا توصله بالموقع أو تعرضه عبر وكيل عام. القضية الكاملة لم تُبنَ بعد؛ المجاني المتاح هو الافتتاح والمعاينات.

## التشغيل والاختبارات

```bash
cd server
npm ci
RAVEN_ENABLE_CREDIT_SIMULATION=1 npm start
npm test
```

يرتبط بـ127.0.0.1 والمنفذ4000 افتراضيًا. بدون المتغير تُرفض المسارات بـ503 باستثناء health. تغيير simulation أو نوع مزود إلى قيمة حية يمنع الإقلاع. القيم في config.example.json بيانات اختبار قديمة، لا سعر معتمد. اختبارات npm تستخدم قاعدة مؤقتة مستقلة ولا تحذف قاعدة الإعداد الحقيقي.

## ما يصلحه هذا الإصدار

- HMAC كامل للمحاكاة بدل تجاوز التوقيع ببادئة. ليس توثيق webhook لأي بوابة فعلية.
- نفس مفتاح طلب الشراء مع مشتري/باقة مختلفة409 دون كشف الطلب الأصلي. عدد الاستحقاقات يُنسخ داخل quote عند الإنشاء؛ تعديلات الباقة اللاحقة لا تغيره.
- POST /dialogue يتطلب requestId ثابتًا بالإضافة إلى userId وcaseId وmessage وpreferAi. نفس الطلب يعيد الرد بلا خصم؛ تغيير محتواه409. هذا تعديل عقد المحاكي فقط، ولا يغير عقد /api/dialogue.
- التوليد المحلي والخصم وحفظ الرد والتقدم ضمن transaction واحدة؛ لا ينفذ اتصال نموذج خارجي داخلها. تعثر الحفظ يعيد الرصيد والتقدم.
- الترحيل002 يضيف simulation_quotes وsimulation_requests دون حذف الجداول السابقة. الطلب القديم المعلق بلاquote يرفض التسوية بـquote_not_available؛ لا نستنتج الاستحقاق من باقة ربما تغيّرت.
- npm run migrate أصبح أمرًا فعليًا للترحيل المحلي. انسخ قاعدة fixture قبل أي تعديل مهم؛ هذا ليس إجراء نسخ قاعدة إنتاج.

## ما لا يقدمه

مصادقة مشترين، بوابة تجريبية أو حية، استرداد مالي، تسوية بوابة، حصص حسابات أو مراقبة مالية. هذه تمنع البيع. لا تُدمج قواعد المحاكاة مع main dialogue بدعوى وجود SQLite. التفاصيل في ../docs/raven-review/PAID-READINESS.md.
